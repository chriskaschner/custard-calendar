### Gaps Summary

Three of four bugs (BUG-01, BUG-02, BUG-03) are fully implemented and wired. The CSS truncation rules exist at the correct selectors, the hero cache now stores and renders `displayName`, and the uncommon badge is suppressed.

BUG-04 is a partial implementation. The `fetchSignalsShared` function in `docs/planner-ui.js` correctly implements the DOW-pattern relevance filter and is backward-compatible (callers without `options.todayFlavor` see no change). However, no page on the main branch currently:

1. Renders signal cards (no `signals-section` or `signals-list` DOM elements exist in any `.html` file)
2. Calls `CustardPlanner.fetchSignals()` with the `{ todayFlavor: ... }` option

The SUMMARY for plan 02 explicitly notes this deferred wiring: "passing todayFlavor from callers is expected to be done when those callers are updated." That wiring was not delivered in phase 33.1, so the observable behavior described in Success Criterion 4 -- "DOW pattern insight cards only render when the signal flavor matches today's FOTD" -- is not yet achievable.

To close this gap, a caller must invoke `CustardPlanner.fetchSignals(workerBase, slug, sectionEl, listEl, 1, { todayFlavor: currentFlavor })` from the page that renders the signals section, and that page must have the signals DOM structure present.
