# Phase 36.1: Hierarchical Rarity Fallback - Context

**Gathered:** 2026-04-08 (assumptions mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Wire the existing flavor-hierarchy scope resolution from metrics.js into route-today.js's 3-gate rarity system. When a store has insufficient data for rarity labeling, fall back through metro -> state -> national scopes. Return both the rarity label and the effective scope so consumers can display context (e.g., "Rare in Madison area").

</domain>

<decisions>
## Implementation Decisions

### Scope Fallback Integration
- **D-01:** Export helper functions (queryDatesForSlugs, computeGapStats, computeGapStatsPerSlug) from metrics.js and import them into route-today.js. Do not duplicate query logic.
- **D-02:** Use early-exit pattern: stop querying wider scopes as soon as sufficient data is found at any scope level. Store -> metro -> state -> national order.

### Gate Threshold Alignment
- **D-03:** Keep the existing 10-appearance / 90-day-span quality gate for store-scope rarity. Use 30-appearance minimum (matching metrics.js MIN_APPEARANCES) as the quality gate for metro/state/national scopes.
- **D-04:** The avg_gap_days thresholds (>150 Ultra Rare, >90 Rare) remain constant across all scopes -- they measure flavor frequency regardless of geographic scope.
- **D-05:** The network suppression gate (>100 stores in 30 days) stays as-is -- it already operates at network scope.

### Normalization Reconciliation
- **D-06:** Unify on `normalize()` from flavor-matcher.js for all D1 queries, since that matches how `normalized_flavor` was populated in the snapshots table. Update metrics.js scope helpers to accept a normalization function parameter rather than using their own internal normalizeFlavorKey().

### API Response Shape
- **D-07:** Add `scope` field to rarity object in /api/today response: `{ appearances, avg_gap_days, label, scope }` where scope is "store" | "metro" | "state" | "national" | null.
- **D-08:** Update social-card.js and planner-domain.js to display scope context when label is present (e.g., "Rare in Madison area" vs "Rare at this store").

### Performance
- **D-09:** Rarity computation remains wrapped in try/catch with null fallback -- no scope query failure should break the /api/today response.
- **D-10:** Accept increased latency only for sparse stores that actually need fallback. Stores with sufficient data return at store scope with no extra queries.

### Claude's Discretion
- Exact wording of scope labels in UI
- Whether to cache scope resolution results in KV
- Test structure for hierarchical fallback scenarios

### Folded Todos
- "Wire hierarchical fallback into rarity labeling" (2026-04-08) -- this is the core work of this phase

</decisions>
