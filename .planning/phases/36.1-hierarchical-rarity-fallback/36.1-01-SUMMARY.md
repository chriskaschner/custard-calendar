# Phase 36.1 Plan 01: Hierarchical Rarity Scope Fallback Summary

Hierarchical scope fallback for rarity labeling: stores with sparse data fall back through metro/state/national scopes using metrics.js helpers, with scope field in API response and unified normalization.

## Tasks Completed

### Task 1: Export scope helpers, unify normalization, write fallback tests (TDD)

**RED:** Created 10 test cases in `worker/test/hierarchical-rarity-fallback.test.js` covering all scope levels, early-exit, error handling, and scope field presence. Tests failed as expected against the pre-existing code.

**GREEN:** 
- Removed `normalizeFlavorKey()` from `worker/src/metrics.js` and replaced all 4 call sites with `normalize()` from `worker/src/flavor-matcher.js` (D-06)
- Added `import { normalize } from './flavor-matcher.js'` to metrics.js

- Added `scope` field to rarity response object
- Updated spoken text with scope-aware phrasing
- Updated existing rarity tests (route-today-rarity.test.js) for new fallback behavior
- All 35 rarity tests pass

### Task 2: Wire hierarchical fallback into route-today.js

Completed as part of Task 1 GREEN phase (the TDD tests exercise the full integration through handleApiToday, so the implementation had to be wired end-to-end).

**Implementation details:**
- Store scope: 10+ appearances AND 90+ day span required
- Wider scopes (metro/state/national): 30-appearance minimum (matching metrics.js MIN_APPEARANCES)
- Metro lookup uses WI_METRO_MAP from leaderboard.js
- State lookup uses STORE_INDEX state field
- National lookup uses TRIVIA_METRICS_SEED planner_features.flavor_lookup
- Each scope query wrapped in try/catch (D-09: non-fatal on failure)
- Early-exit pattern: stops at first scope with sufficient data (D-02)
